Поиск аномальных респондентов в активности поисковых запросов SoS

Команда запуска
python solution_Семеновых_Екатерина_Александровна_ШЦТ_111.py

Описание алгоритма

Аномалия – доля респондента в дневном OTS бренда (share = daily_ots / total_brand_ots) превышает адаптивный порог.

Score – значение доли share (чем выше, тем аномальнее).

Порог – вычисляется для каждого бренда отдельно на основе исторических данных за 30 предыдущих дней: threshold = median(share_history) + 4.5 * MAD(share_history), где MAD – медианное абсолютное отклонение.

Почему подход разумен:
- Интерпретируемость: каждая аномалия имеет численную причину в файле anomaly_reasons.csv.
- Адаптивность: пороги рассчитываются индивидуально для каждого бренда.
- Робастность: MAD устойчив к выбросам в исторических данных.
- Обнаружение только высокой активности: условие share > threshold, малый OTS уже отсечён параметром min_daily_ots.

Выходные файлы:

- output/anomalies.csv – пары (SubjectID, researchdate) для удаления.
- output/anomaly_reasons.csv – детальные причины аномалий.
- output/plots/ – графики: total_ots_before_after.png, category_ots_change.png, daily_anomaly_count.png, а также дополнительные по полу, возрасту, региону, федеральному округу, ресурсам, категориям, и график изменения OTS бренда.
